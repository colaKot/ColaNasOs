# ADR-0006 版本目录式更新器 + ed25519 签名

- 状态：已采纳（2026-10-31）
- 相关：[09-任务清单 SP4-01 / SP4-02](../09-任务清单.md)

## 背景

应用自我更新最常见的失败模式是「原地覆盖到一半崩溃」——旧版本被破坏、新版本不完整，
用户只能重装。NAS 场景还要求能一键回到上一版。

## 决策

1. 每次更新解到 `versions/D<NNN>`，**先写临时目录再原子 rename**，永不原地覆盖；
2. `current.json` 是唯一指针，切换也是一次原子写；
3. `manifest.json` = 文件 sha256 清单 + ed25519 签名（`canonicalPayload` 键排序保证可复现），
   配置公钥时强制校验，篡改报 `E_SIGNATURE`；私钥不入库（`*.pem` 已忽略）；
4. **默认禁止降级**，`rollback()` 走显式路径切回上一目录。

## 后果

**正面**：更新失败不影响当前版本；回滚是 O(1) 的指针切换；供应链篡改可检测。

**负面**：磁盘占用为「版本数 × 体积」，需要保留策略（未实现自动清理）；
签名密钥的分发与轮换是运维负担。

## 替代方案

- **electron-updater 默认流程**：原地替换 + 需要代码签名证书，失败即损坏，且不满足回滚要求。
- **整包重装**：用户数据在 `${dataDir}` 不受影响，但体验与增量更新不可接受。
