# ADR-0002 列表分页统一用排序键游标

- 状态：已采纳（2026-10-28）
- 相关：[02-服务端内核](../02-服务端内核.md)、[进度与下一步 §9](../进度与下一步.md)

## 背景

相册时间轴、影视标题序、音乐专辑序都需要稳定分页。`OFFSET` 在数据增长后是线性扫描，
且并发写入会导致「翻页时漏条目 / 重复条目」。

## 决策

- 一律用**排序键 cursor**：`<sortKey>|<id>`（如 `taken_at|42`）或 JSON 编码的复合键
  （如 `{"title":"abc","id":7}`），用 `WHERE (k, id) < (?, ?)` 取下一页；
- cursor 对客户端不透明，只回传 `nextCursor`；
- 兼容键含分隔符的情况（JSON 编码，而不是裸拼接）。

## 后果

**正面**：翻页成本与页大小相关，与总量无关；并发写入下不重不漏。

**负面**：不支持随机跳页（第 N 页），只支持「下一页」；排序键必须有稳定次序（故总是追加 `id` 次键）。

## 替代方案

- `LIMIT/OFFSET`：实现简单但深翻退化，且在写入并发下不稳定，仅用于内部小表。
- keyset + 反向游标（上一页）：未实现，UI 只提供「加载更多」。
