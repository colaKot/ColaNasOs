# ADR-0005 取消 service / docker / P2P / remote

- 状态：已采纳（2026-10-31）
- 相关：[09-任务清单 SP3-10 / SP3-12](../09-任务清单.md)、[06-产品与运维](../06-产品与运维.md)

## 背景

早期任务清单里有「service（systemd / Windows 服务注册）」「docker 管理」「p2p / remote
（DDNS、配对码中继）」三类能力。它们都需要长期维护的平台适配与外部基础设施。

## 决策

1. **docker / service 明确不做**：NAS OS 以 Electron 应用 + 后台内核进程形态交付，
   开机自启由 Electron 的登录项机制承担；
2. **P2P / remote 取消**：跨设备同步改为局域网内 HTTP 同步（`/sync/*`），
   DDNS 与配对码中继不再自建；
3. 任务清单里保留条目并写明「不做」，避免后来者重复评估。

## 后果

**正面**：安装包不依赖 root / 管理员提权；不用维护中继服务器与 NAT 穿透；交付面收敛。

**负面**：跨公网访问需要用户自备 VPN / 反向代理；没有「一键开服」体验；
无法管理同机容器。

## 替代方案

- **内置 docker 面板**：与「单机 NAS」定位重叠且依赖 Docker Desktop，否决。
- **自建中继**：需要长期运营的公网带宽与合规成本，非本项目范围，否决。
