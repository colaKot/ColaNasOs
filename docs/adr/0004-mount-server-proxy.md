# ADR-0004 不做 FUSE 真挂载，改为服务端代理读写

- 状态：已采纳（2026-10-28）
- 相关：[09-任务清单 SP3-07](../09-任务清单.md)、[进度与下一步 §14](../进度与下一步.md)

## 背景

远程目录（WebDAV / SMB / 网盘）有三种接法：内核 FUSE 挂载成本地路径、客户端各自挂载、
服务端代理读写。FUSE 看起来最优雅——文件页与播放器直接当本地路径用。

## 决策

- **不实现 FUSE**；`src/modules/mount` 提供「远程目录」语义：浏览 / 下载（透传 Range + ETag）/
  上传 / 新建目录 / 删除文件，全部走 HTTP 代理；
- 播放与阅读不复制整个文件：用 `/mount/download-url` 签发 5 分钟 `mount:read` 令牌，
  播放器 / 阅读器按 Range 拉取；
- 只读挂载在服务端拒绝写（403），凭据 AES-256-GCM 加密落库。

## 后果

**正面**：Windows（WinFsp）/ Linux（libfuse）/ macOS（macFUSE）行为一致，无需安装驱动；
权限、审计、限速、缓存都能落在内核；安装包不背平台依赖。

**负面**：远程目录不会出现在「文件」页的本地 VFS 列表里（需 UI 聚合，未做）；
第三方应用无法用本地路径直接访问远程文件；大文件首次拖动依赖 Range 支持。

## 替代方案

- **FUSE 挂载**：三端驱动与权限模型差异大，崩溃会挂死资源管理器，否决。
- **客户端直连网盘**：凭据要下发到每台设备，审计与限速失控，否决。
