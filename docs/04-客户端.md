## 10\. 客户端方案 K1：Flutter 单栈 6 端 + AppleTV 原生壳

### 10.1 决策与理由

-   **UI 层选 Flutter**：Flutter 是唯一能覆盖桌面 + 移动 + web 且**原生播放/文件能力完备**的栈。
-   **完全重新设计**：视觉、交互、组件、主题**从头设计**（§0.1）。
-   **第三方库从上游引入**：播放器（media3 / fvp）、阅读器（foliate-js）、PDF（pdfrx）等一律从 pub.dev / 上游仓库引入。
-   端覆盖：`desktop(win/mac/linux)` / `mobile(android/ios)` / `web` / `tv_android` / `tv_apple` / `harmony`。

### 10.2 多端策略（6 端 Flutter + AppleTV 原生壳）

| 端 | 做法 | 说明 |
| --- | --- | --- |
| desktop | Flutter Windows/macOS/Linux | 现有实现延续 |
| mobile | Flutter Android/iOS | 现有实现延续 |
| web | Flutter web（**试验 `--wasm`/skwasm**） | 渲染密集场景收益明显，需验 `webview_flutter`/`pdfrx`/`quill` 兼容性 |
| tv\_android | Flutter 自研 **D-pad 遥焦** | 复用一套 UI；轻量 |
| tv\_apple | **保留 Swift 原生壳**（共用同一 API 契约与设计规范） | ⚠️ Flutter 官方无 tvOS 引擎、社区方案不成熟 ⇒ **不承诺"Flutter 统一"**，见 §15 红线 7 |
| harmony | **`flutter_ohos`（OpenHarmony SIG fork）** | 非官方 fork，版本需对齐 Flutter 主线 |

### 10.3 主端结构重构（§11 详述）

-   拆包：`nas_core`（网络/DB/同步/契约产物）/ `nas_ui`（组件+主题）/ `nas_media`（播放器/阅读器封装）。
-   响应式布局：**一套逻辑 + 两套布局**，消灭桌面/移动两套并列实现。
-   契约驱动：ApiClient / AppRegistry / i18n 全部生成。
-   状态管理：**GetX 保留**（518 处，不强迁），但规范 `Obx` 读点边界与 controller 职责。

### 11.1 移动端后台任务（v3.3 新增）

- Android：`WorkManager` 调度相册备份，约束（充电 / Wi-Fi / 电量）可配。
- iOS：`BGTaskScheduler` + 后台 `URLSession`。
- 统一要求：**可断点、可限速、有进度**；与现有 `photoBackup` 逻辑对齐。

### 11.2 离线与弱网（v3.3 新增）

- 请求层：重试（指数退避）+ 幂等键；断网时入本地队列。
- 缓存层：列表/详情 LRU + 离线快照（`server+uid+year` 命名空间）。
- 冲突：写操作**以服务端为准**，客户端仅提示"已覆盖 / 已合并"。

### 11.3 Drift 本地库迁移（v3.3 新增）

- 每次 schema 变更产一个 **Drift migration**（版本号 + 迁移脚本）。
- 升级前自动备份本地库；迁移失败回滚并提示。
- 禁止"删库重建"式升级（会丢同步 baseline 与播放进度）。

## 39. 设计系统（v7.0 新增）

> UI **完全重新设计**（§0.1），6 端共用一套设计语言。

### 39.1 Design Tokens

| 类 | 内容 |
| --- | --- |
| 色彩 | 语义色（primary/onPrimary/surface/…）+ 主题槽（不写死色值） |
| 间距 | 4 / 8 栅格（4·8·12·16·24·32·48） |
| 圆角 | 4 / 8 / 12 / 16 / pill |
| 字体 | 标题 5 级 + 正文 3 级 + 等宽；行高与字重固定 |
| 层级 | elevation 0–3 + 遮罩色 |
| 动效 | 时长 150/250/400 ms + 标准缓动 |
| 图标 | 统一图标库 + 尺寸档（16/20/24/32） |

### 39.2 组件清单（按类型）

| 类型 | 组件 |
| --- | --- |
| 导航 | 侧栏、顶栏、面包屑、Tab、分页器 |
| 输入 | 输入框、搜索框、下拉、日期、上传、开关、滑块 |
| 展示 | 卡片、列表项、表格、网格、空态、骨架屏 |
| 反馈 | Toast、Snackbar、对话框、抽屉、进度、加载 |
| 媒体 | 封面、缩略图墙、播放器控件、阅读器壳 |

### 39.3 交互规范

- **状态四件套**：加载 / 空 / 错误 / 无权限，每页必须齐备。
- **响应式**：断点 desktop / tablet / mobile；**一套逻辑 + 两套布局**（§11）。
- **TV**：D-pad 焦点模型（§43）。
- **禁止**：无反馈的按钮、超过 2 级的面包屑、模态套模态。

## 43. 无障碍与多端输入（v7.0 新增）

### 43.1 基线

- **WCAG 2.1 AA**：正文对比度 ≥ 4.5:1、大字 ≥ 3:1。
- **焦点可见**：任何可交互元素都有焦点态。
- **语义标签**：图标按钮必须有可读文本（`Semantics` / `accessibilityLabel`）。
- **不做纯色传达**：状态不能只靠颜色（同时给图标/文字）。

### 43.2 多端输入

| 端 | 规范 |
| --- | --- |
| desktop | Tab 序合理；快捷键可配；Esc 关闭浮层；右键菜单可选 |
| mobile | 触屏手势（滑动返回 / 长按多选）；点击目标 ≥ 44×44 |
| TV | **D-pad 焦点模型**：焦点记忆、跨区域跳转、返回键语义统一 |
| web | 键盘可达；浏览器缩放 200% 不破版 |

## 62. 客户端 UI 架构（v9.0 新增）

| 端 | 结构 |
| --- | --- |
| desktop | **多窗口**（每 App 一窗）+ **标签页**（同 App 内多标签）；每标签独立导航栈 |
| mobile | 单栈 + 底部导航 |
| web | 单页 + 路由 |
| TV | 焦点层级（§43） |

- **窗口状态持久化**：位置 / 尺寸 / 标签集合，重启恢复。
- **快捷键**：全局（唤起搜索、切换 App）+ 局部（列表/播放器），可配置。
- **状态四件套**强制（§39.3）。

> - 门禁：`npm run gen:caps.check`（生成物未过期）+ `npm run caps.check`（本表逐格与契约一致、App 归属存在、外壳已接线），均已进 `npm run verify`。
