### v8.2 许可口径修正（2026-10-27）

> 澄清：**本项目本身就是 GPL-3.0**，因此 v8.1 的"AGPL 清零 / GPL 源码义务"**并非新增负担**，主要影响是"解释成本"与"客户政策"，而非法律相容性。

- **红线 13 放宽为「默认禁止 + 例外五条件」**：独立进程 / 不改源码 / 不静态链接 / 法务书面确认 / SBOM 标注。**保留未来引入 openlist（国内网盘能力）的可能**。
- **FFmpeg 补兼容说明**：GPL-2.0+ 可升级至 GPLv3，与本项目 GPL-3.0 **兼容、无冲突**；义务仅为"随包提供源码或书面要约"。
- **§42 发布检查**改为"AGPL **默认 0**，例外须在 SBOM 标注 + 法务书面确认"。

### v8.1 许可合规调整（2026-10-27）

- **AGPL 清零**：`sftpgo`（协议服务）与 `openlist`（网盘聚合）均为 AGPL-3.0 ⇒ **不采用**。
  - 协议服务改由 **`rclone serve`（MIT）** 承担（sftp / webdav / ftp / http）；
  - 网盘挂载改由 **`rclone` 多后端（MIT）+ 内核 VFS 聚合**（国内网盘按需自研 adapter，模块更名 `netdisk`）。
- **新增红线 13**：禁止 AGPL 依赖；评审发现即阻断。
- **FFmpeg 定案**：继续 **GPL 构建**并随包分发，同时**提供源码与构建参数**（GPL-3.0 §6 义务）；以独立进程调用，不影响本项目自身许可。
