## 9\. 契约单一真源与代码生成

```
TypeBox schema（内核 + 各域模块 route）
        │
        ▼
   ContractRegistry  ──►  OpenAPI 3.0.3（/openapi.json，`@fastify/swagger` 稳定输出）
        │
        ├─► ① Dart ApiClient 生成（packages/nas_core）
        ├─► ② i18n 键骨架生成（13 语言，仅键 + 占位符）
        └─► ③ AppRegistry（6 端入口注册表）生成



```

**规则**：任何路由/字段/i18n 键的新增**只改 TypeBox schema**，生成物由 `tool/gen.js` 从**运行中的内核实例**导出，**禁止手写**；`npm run gen.check` 校验磁盘与生成一致（0 diff）。

**生成物现状（SP1-01）**：`npm run gen:client` → `packages/nas_core/lib/api/client.dart`（每个 `operationId` 一个方法，JSON body 用 DTO、二进制 body 用 `List<int>`）+ `models.dart`（`components.schemas` → DTO，含 `fromJson`/`toJson`）。手写部分只有 `transport.dart`（`IoTransport`）与 `api_error.dart`。

### 9.1 文件传输协议（v3.3 新增）

| 环节 | 规范 | SP0 状态 |
| --- | --- | --- |
| 上传 · 预检 | `POST /api/v1/files/check`，入参 `{path,size?,hash?}` → `{path,exists,uploadId,uploaded[],chunkSize}` | ✅ 秒传判定 + 已收分片 |
| 上传 · 分片 | `POST /api/v1/files/chunk?path&index&total`，`application/octet-stream`，单请求 ≤ 64 MB；先写 `.tmp` 再 `rename`（不留半片） | ✅ |
| 上传 · 合并 | `POST /api/v1/files/merge`，入参 `{path,total,size?,hash?}`；**幂等**：目标已存在且一致返回 `skipped:true`；缺片 `409`，尺寸/hash 不符 `422`（不落盘） | ✅ 整体 sha256 校验 |
| 断点续传 | 服务端按 `uploadId`（目标相对路径派生）保留已收分片，客户端凭 `check` 续传 | ✅ |
| 下载 | `GET /api/v1/files/download?path=`：强 ETag（尺寸+mtime）、`If-None-Match` → `304`、`If-Range` 失配回 200 全量、单段 `Range` → `206`、越界 → `416`（带 `Content-Range: bytes */size`），全程流式 | ✅ |
| 大文件 | 推荐流式转发，**禁止整文件进内存** | ⚠️ merge 逐片读取（峰值 = 单片大小）；SP0-10 转流式 |

> 逐片 `sha256` 校验（每片随请求带 hash）在 SP2 随传输协议加固补入；SP0 用整体 hash 兜底。

### 9.2 统一错误契约（v3.3 新增）

```ts
interface ApiError {
  code: string;        // 'FILE_NOT_FOUND' | 'PERMISSION_DENIED' | ...
  message: string;     // 面向用户，已本地化
  details?: unknown;   // 结构化上下文（不含敏感信息）
  traceId: string;     // 关联日志
}
```

- 错误码表集中在 `contracts/errors.json`，生成客户端常量。
- **禁止**返回裸字符串错误；错误码 → i18n key 映射统一维护。

**实现落点（2026-10-29）**

| 产物 | 说明 |
| --- | --- |
| `contracts/errors.json` | 16 个错误码，含默认 HTTP 状态与中文默认文案 |
| `kernel/errors.ts`（生成） | `Err.badRequest` 等常量 + `ERROR_STATUS` / `ERROR_MESSAGE`；**值仍是原字符串**，与旧响应完全兼容 |
| 迁移 | 全仓 **286 处** `error: 'xxx'` → `error: Err.xxx`（26 个文件），行为零变化 |
| 门禁 | `errors.check`：代码用了契约里没登记的码 → 失败；仍在用裸字符串 → 失败；契约里有但没人用 → 只告警；`gen:errors.check` 防止生成物过期 |
| 响应形态 | `kernel/index.ts` 的 `onSend` | 4xx/5xx 的 JSON 统一补 `code`（= `error`，旧客户端不受影响）与 `traceId`（`req.id`，可对照 `kernel.log`）；handler 回传的结构化字段（`need` / `rule` / `path` / `required` / `scopes` / `reason` / `limit`）收进 `details`，原字段保留 |
| 契约 | 15 个 `*Error*` schema | 全部声明可选 `code` / `traceId` / `details`（`Type.Record(Type.String(), Type.Unknown())`），OpenAPI 与 Dart 模型（`Map<String, dynamic>? details`）同步 |
| 客户端 | `packages/nas_core/lib/api/api_error.dart` | `ApiError` 解析 `code` / `details` / `traceId`；`isUnauthorized` / `isForbidden` / `isRetryable` 判定不受影响 |
| 断言 | `smoke:auth` **33/33** | 403 时 `details={need:'read',rule:null,path:'/secret'}`、`traceId` 非空、`code==error` |

> 说明：响应体是 **`{error, message, code, traceId, details?}`**——比 §9.2 蓝图多了 `error`。
> 保留 `error` 是为了不破坏 30+ 处冒烟与旧客户端；等所有消费方都读 `code` 后再切换字段名（走 `verify:contract`）。
> `details` 由内核从 handler 的结构化字段**自动收拢**，模块不需要改返回体。

### 9.3 分页规范（v3.3 新增）

- 一律 **cursor 分页**：请求 `{cursor?, limit}` → 响应 `{items, nextCursor}`。
- **禁止 offset 深翻**（大表越翻越慢）；时间轴/相册按排序键编码 cursor。
- `limit` 上限 200。

### 9.4 ID 与软删除规范（v3.3 新增）

| 项 | 规则 |
| --- | --- |
| 主键 | `file_hash` 为跨域关联主键；**生成规则固定且不可变**（改规则 = 全库重算） |
| 内容去重 | 用 `content_md5`（惰性计算），**不得**用 `file_hash` 冒充内容哈希 |
| 软删除 | 统一 `in_trash` 字段；所有查询默认过滤，回收站视图显式放开 |
| 物理删除 | 仅回收站清理路径允许，且必须记审计 |

### 9.5 时间与时区规范（v3.3 新增）

- 存储：一律 **UTC epoch**；另存原始时区偏移（EXIF 无时区时记 `null`）。
- API：返回 ISO-8601（含偏移）。
- 展示：按客户端时区渲染；**分组/排序一律用 UTC**，避免跨时区错位。

### 9.6 API 覆盖核对机制（v5.0 新增）

- 基线规模：**550+ 路径**。
- 新仓 `ContractRegistry` 导出**新 OpenAPI**。
- `tool/check/api-coverage.ts` 做**域级比对**：按路径首段（`/api/photo`、`/api/video`…）统计「旧有新无」，输出差异报告。
- **门禁**：「旧有新无」清单必须为空，或在 §16 风险登记逐条豁免。
- 不要求路径逐字一致（新项目允许重设计），但**能力必须一一对上**。

## 21\. API 版本化与弃用（v3.0 新增）

-   所有接口统一前缀 **`/api/v1/**`**。
-   **OpenAPI diff 检测**：CI 中对比基线，**破坏性变更（删字段/改类型/改语义）直接失败**。
-   **弃用流程**：响应头 `Deprecation: true` + `Sunset: <date>`；至少保留 **2 个版本**。
-   目的：避免重复"553 路径包袱"的历史。

### 21.1 版本化与代码生成的联动（v3.3 新增）

- OpenAPI 的 `info.version` 必须与 `/api/v1` 的 `v1` 对齐。
- 生成的 Dart client 记录 `apiVersion`；**major 变更 = 新命名空间**（如 `ApiV2`），**不原地改签名**。
- 客户端可同时持有 v1/v2 适配器，便于灰度切换。

## 23\. i18n 语言清单与翻译流程（v3.2 已核实）

> ✅ **已核实（2026-10-27）**：三端均为 **13 种语言** —— `electron_server/language/` 13 个、`harmony_client/.../locales/` 13 个、`flutter_client/lib/core/languages/` 13 个。  
> 原"14 个"的差异来源是 `electron_server/language/zh.json`：内容为 **`{}`（2 字节）**，无任何代码引用（`i18nUtil.js` 的 `locales` 数组只有 13 项）⇒ **已删除**（备份 `_patch_backup/i18n_cleanup_20261027/`）。

-   **单一真源**：`contracts/locales.json` 固化 13 项（`code` / 原生名 / `enabled` / **三端文件名映射**）：`zh-CN` ↔ `zh-CN.json`（Electron）/ `zh_cn.dart`（Flutter）/ `zh-cn.json`（鸿蒙）。
-   **流程**：键由 `i18nRegistry` 生成骨架 → **按术语表翻译（§0.1）** → **缺键 CI 门禁**（任一语言缺键即失败）。
-   **占位符**：全局统一一种语法（推荐 `{name}`），鸿蒙侧转换由生成器完成。
-   ⚠️ 禁止在代码里拼接用户可见文案。

### 23.1 实现落点（2026-10-29）

| 层 | 文件 | 说明 |

## 38. 行为规格与对照用例（v7.0 新增）

> 每个域必须先产出**可执行用例**做行为验证。

| 产物 | 位置 | 说明 |
| --- | --- | --- |
| 行为规格 | `spec/<domain>.md` | 用自然语言描述"给定什么 → 期望什么"，**由人根据旧程序黑盒观察撰写** |
| 对照用例 | `cases/<domain>/*.json` | 机器可执行：输入 + 期望输出 |
| 执行器 | `tool/check/behavior.ts` | 跑用例，对比新实现输出；失败即阻断 |

用例格式：

```json
{
  "name": "photo.timeline.page1",
  "given": { "user": "readonly", "limit": 30 },
  "when": { "method": "GET", "path": "/api/v1/photo/timeline", "query": { "limit": 30 } },
  "then": { "status": 200, "shape": ["items", "nextCursor"], "orderBy": "capturedAt:desc", "itemsMax": 30 }
}
```

**覆盖要求**（每域至少）：

- 权限边界（匿名 / 只读 / 普通 / 管理）
- 错误码（不存在 / 无权限 / 参数错）
- 分页与排序稳定性（cursor 不跳项）
- 时间与时区（§9.5）

⚠️ **用例来源红线**：只能来自**黑盒观察与需求**，**禁止从旧源码反推/抄写断言**（否则等于变相复制逻辑）。

## 40. 翻译工作流（v7.0 新增）

> 13 语言**按术语表翻译**（§0.1）。

| 环节 | 做法 |
| --- | --- |
| 语言清单 | 单一真源 `contracts/locales.json`（13 项，见 §23） |
| 术语表 | `contracts/glossary.json`：核心术语统一译法（如 "库/来源/相册/人物"） |
| 提取 | `i18nRegistry` 生成键骨架 |
| 初翻 | 机器翻译打底（**必须标注"未审校"**） |
| 审校 | 母语者/专业译者；核心语言（zh-CN / en-US）人工直译 |
| RTL | `ar-SA` 布局镜像、图标方向、数字格式 |
| 门禁 | 缺键 0 · 占位符一致 · 术语表命中 |

## 49. REST 设计规范（v8.0 新增）

| 项 | 规则 |
| --- | --- |
| 资源命名 | 复数名词：`/photos`、`/albums`、`/libraries` |
| 方法语义 | `GET` 幂等、`PUT` 幂等、`POST` 非幂等、`DELETE` 幂等 |
| 状态码 | 200 / 201 / 204 / 400 / 401 / 403 / 404 / 409 / 422 / 429 / 500 |
| 批量 | `POST /<resource>/batch`，返回逐项结果（部分成功不整体失败） |
| 过滤/排序/分页 | `?filter=&sort=&cursor=&limit=`（§9.3） |
| 错误 | 统一 `ApiError`（§9.2） |
| 版本 | `/api/v1`（§21） |

## 53. 版本兼容矩阵（v8.0 新增）

| 服务端 | 客户端 | 行为 |
| --- | --- | --- |
| 新（同 major） | 旧 | 保持向后兼容；不兼容字段返回默认值 |
| 新（跨 major） | 旧 | 返回 **426 Upgrade Required** + 最低版本提示 |
| 旧 | 新 | 客户端探测服务端版本，**自动降级**不可用功能 |

- 兼容承诺：**同一 API major 内向后兼容**；破坏性变更升 `/v2`（§21.1）。
