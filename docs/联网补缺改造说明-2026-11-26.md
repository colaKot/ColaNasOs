# 联网按需补缺 + 3 组合并改写：改造与实测（2026-11-26）

> 按「RSS 为主 + 联网按需补缺 + 8 类合并成 3 组改写」落地的改造说明与真实 token 实测。

## 一、改了什么

| 文件 | 改动 |
| --- | --- |
| `src/modules/blog/web-fill.ts`（新增） | `fillGapsByWebSearch`：RSS 抓完后，只对**缺口类别**用 `deepseek_web_search` 补素材（摘要 120-150 字），返回合并素材与用量 |
| `src/modules/blog/script.ts` | 新增 `REWRITE_GROUPS` / `groupPrompt` / `parseGroups` / `composeGroup`；`composeScript` 由「8 类各调一次」改为「3 组合并调」；SYSTEM_PROMPT 输出格式段改为通用（由各 prompt 各自声明） |

## 二、关键设计

- **只补缺口**：某类 `已抓条数 >= 目标条数` 就不联网。源够时补缺 0 次调用、0 token。
- **联网只取素材、不改写**：素材仍交给 `composeScript` 走 `json_object` 强约束改写，格式 / 字数校验 / 分类排他 / 去重全保留。
- **text 模式**：带 `deepseek_web_search` 时 `response_format` 必须是 text（否则 400），所以让模型把素材包成 `{"articles":[...]}` 再容错解析。
- **搜索免费**：服务端搜索工具不计费，只按 Token 计（用量里记 `searchCalls` 仅统计）。
- **3 组划分**：综合（国内+国际）/ 科技AI（国内外科技 + 国内外 AI）/ 财经（国内+国外）。同组"同口径"，分类更稳；system prompt 由 8 份降到 3 份。

## 三、实测 token（真实 `api.deepseek.com` / `deepseek-flash`，目标 30 条）

| 场景 | 调用次数 | 输入 | 输出 | 合计 token | 成稿 | token/条 |
| --- | --- | --- | --- | --- | --- | --- |
| **改造前基线**（8 类，10 条） | 9 | 15,246 | 2,432 | **17,678** | 10 条 / 2,322 字 | 1,768 |
| **改造后·源够**（RSS 81 条，补缺 0） | 4 | 12,757 | 5,539 | **18,296** | 29 条 / 6,028 字 | **631** |
| **改造后·源缺**（补 4 类共 16 条） | 4+4 | 26,514 | 7,539 | **≈34,053** | 30 条 | 1,135 |

**怎么读这张表：**
- 合并成 3 组后，**单条 token 从 1,768 降到 631（省约 64%）**；29 条的总 token 几乎等于改造前 10 条（18,296 vs 17,678）。
- **源够时联网零成本**（补缺 0 次调用），这是"按需补缺"的核心收益。
- **补缺单价约 985 token/条**（含搜索结果进上下文）：4 类各缺 4 条 = 16 条，花 15,757 token、9 次搜索、17.9s；4 类全部补足。
- 全场景（30 条 + 补 4 类）约 3.4 万 token，比"改造前 30 条"（按 1,768/条估算约 5.3 万）**省约 30%**。

## 四、补缺效果验证

- 人为让后 4 类（国内AI / 国际AI / 国内财经 / 国外财经）全空，各缺 4 条：
  - 4 次调用全部**补足**（各 4 条），素材来源真实（央视网 / 新华社 / 证券时报 / i黑马 等），摘要 128-188 字。
- **分类准确性弱于 RSS**：实测有一条"我国牵头 AI 国际标准"被归到「国际人工智能」。下游 `composeScript` 的 SYSTEM_PROMPT 有地域口径复判，会再筛一次，但建议后续给补缺 prompt 加更强的地域约束。

## 五、如何启用

1. 设置 → 大模型，填好 DeepSeek Key（已有）。
2. **打开「联网搜索」开关**（`webSearch`，默认关闭）——这是补缺的总开关。
3. 生成一期时，RSS 抓不到的类别会自动联网补，日志里会打印「联网补缺：XX-缺N，开始联网检索」。

## 六、已知限制

1. **字数仍 190-230，未到 250-300**：这是 `deepseek-flash` 改写倾向问题（第 2 轮 PoC 已证：素材给到 155-179 字，改写仍 196-223 字）。要 250-300 需另做「扩写补调」或调 `MIN_CHARS/MAX_CHARS`。
2. **补缺分类准确性弱于 RSS**（见四），需在补缺 prompt 里强化地域/排他。
3. 补缺与改写共用同一模型；补缺会多花一次「搜索上下文」的输入 token，属于获得"源稳定"的代价。
4. 补缺的素材 `link` 为空（搜索结果未取 URL），不影响改写，但「引用链接」清单里这类条目的 url 为空。
