## 0.1 实现原则（v6.0 定案）

> ⭐⭐ **ColaNasOs 是独立实现的项目：代码、界面与数据模型均为本项目自有。**

| 项 | 规则 |
| --- | --- |
| 许可 | 本项目采用 **GPL-3.0**，由本项目自主发布 |
| 源码 | **自有实现**：代码按本项目架构编写（Dart / TypeScript / ArkTS / Swift / Kotlin） |
| UI | **自有设计**：视觉、交互、组件实现均按本项目规范 |
| 翻译 | **自有译文**：13 种语言按本项目术语表翻译（`contracts/glossary.json`） |
| 数据 | **从空库开始**：数据库由本项目迁移脚本建立（§22） |
| 第三方依赖 | 仅从**各自上游**引入（pub.dev / npm / GitHub 原仓库） |
| 功能范围 | 按产品需求定义（功能点见附录 B） |
| 实现口径 | 高阶能力按**行为与算法口径**实现：相册智能 / 足迹地图 / 记忆 / 影视库 / 影视发现 |
| 验证 | 用**可执行用例**做行为验证（`docs/behavior-用例指南.md`） |

> 2026-10-28 修订：相册 / 影视 / 发现三条线按**行为与算法口径**实现（像素聚簇、geohash 格集合、
> KNN 投票、去重预演/撤销、相似度阈值、PP-OCR 流程、库类型语义等），代码按本项目的
> Fastify + TypeBox + Kysely / Flutter + nas_core 结构组织。

**判定标准**：本项目不含任何外部实现的源码。

## 1\. 背景与目标

### 1.1 现状基线

**规模**：6 端 + 2 个 web 站点。服务端 `electron_server/src`（34 个 api 模块、53 个 utils、`workers/ai` 四条 ONNX 队列）；客户端 `flutter_client/lib/modules`（32 个 module × 四层）；独立端 `photo_client` / `music_client` / `sync_client` 以 `path` 依赖主端；另有 `harmony_client`(ArkTS) / `tv_android`(Kotlin) / `tv_apple`(Swift)。

**8 条根因（重构的靶子）**：

| # | 根因 | 具体表现 |
| --- | --- | --- |
| 1 | 单进程巨石 | API + AI 四队列 + 转码 + 索引 + 文件监控挤在一个 Electron 主进程 + `worker_threads` |
| 2 | 无统一调度层 | 每条 AI 流水线各自拉起/回收，无队列/优先级/限流/暂停/进度 |
| 3 | 无迁移框架 | 表结构靠手写 `ensureColumns`；**新增表=必须整包重打** |
| 4 | 契约非单一真源 | 新模块改 4 处入口；桌面/移动两套并列 UI；鸿蒙映射手写；OpenAPI 靠 Express4 `_router` |
| 5 | i18n 双份手工 | Flutter 13 文件 + 鸿蒙 13 文件，键手抄、两套占位符 |
| 6 | 构建/发布脆弱手工 | asar 原地重写热更（必须重启）；web 产物手动拷两处 |
| 7 | 依赖被 ABI/ESM 锁死 | Electron 37 卡死、ONNX 1.20 卡死、Express 不可升 5、纯 ESM 包不可用 |
| 8 | 检索无索引 | 语义/以图搜图走全量余弦；时间轴检索每次现算 |

### 1.2 目标

-   **更快**：启动秒开；API 不被 AI/转码抢占；缩略图/转码/AI 真并行；检索走向量索引。
-   **更高效**：契约单一真源；新增域 = 加一个模块目录，零手抄入口/i18n。
-   **多端统一**：一套 Flutter 代码覆盖 6 端，消除"桌面/移动两套实现"。

### 1.3 非目标（本轮明确不做）

-   ⏸️ **插件框架（B）**：不做 manifest 驱动 / 运行时热插拔（保留为可选增量，见 §5.3）。
-   ⏸️ **Schema 驱动 UI（C3）**：不做通用渲染器。
-   ⛔ 不换客户端框架（Flutter 保留）。
-   ⛔ 不引 PostgreSQL / Redis / K8s（单机 NAS，SQLite + 本地进程通信）。
-   ⛔ 不为"新"而升 ONNX（见 §15 红线）。

## 2\. 战略前提：新项目解锁了什么

> **前提：本项目没有老用户、不存在覆盖升级包袱。**

| 原本被锁死 | ColaNasOs 可以做 |
| --- | --- |
| `name` / `appId` / `bundleName` 不能改 | **自由定标识**（一次定死，见 §13） |
| Express 4 不能升（OpenAPI 抓 `_router`） | **换 Fastify**，schema 即契约 |
| asar 原地重写热更 | **版本目录式更新器** |
| 纯 ESM 包不可用 | 服务端 **TS + 规范模块**，无 CJS/ESM 撕裂 |
| 必须逐字兼容 553 路径 | **API 可重新设计**（功能全覆盖即可） |
| `ensureColumns` 手写迁移 | **正式迁移框架**（Kysely migration） |

> ⚠️ 仍要背的工程约束：Electron ABI 原生模块、ONNX 版本回归、SQLite 999 变量上限、单实例锁。见 §15。

## 3\. 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│  Electron 外壳（安装 / 单实例 / 托盘 / 更新器 / 自动启动）          │
├──────────────────────────────────────────────────────────────┤
│  Kernel 内核（TypeScript，单一入口）                             │
│  ModuleRegistry │ Router(Fastify) │ Auth │ Db+Migration │        │
│  TaskQueue │ EventBus │ ResourceMgr │ I18nRegistry │             │
│  ContractRegistry(OpenAPI 单一真源) │ SidecarSupervisor │ Updater │
├──────────────────────────────────────────────────────────────┤
│  Domain Modules（服务端域模块，目录即模块）                        │
│  files │ photo │ video │ music │ book │ notes │ monitor │
│  sync │ discover │ encryptedSpace │ transfer │ security │ …      │
├──────────────────────────────────────────────────────────────┤
│  Sidecars（重型后台，独立进程 + JSON-RPC over named pipe）        │
│  ai-infer(ONNX)  │  media(ffmpeg/缩略图)  │  indexer  │  sync   │
├──────────────────────────────────────────────────────────────┤
│  Flutter 单栈客户端（6 端）  ◀── OpenAPI 契约 ──▶  上文内核        │
│  packages: nas_core / nas_ui / nas_media                        │
│  apps: desktop / mobile / web / tv / harmony                    │
├──────────────────────────────────────────────────────────────┤
│  Storage: SQLite(better-sqlite3) + sqlite-vec  │  文件系统        │
└──────────────────────────────────────────────────────────────┘



```

**三条主线**：

1.  **内核只做通用能力**：认证、权限、DB、迁移、队列、事件、资源、i18n、契约、进程守护。
2.  **域功能一律进域模块**：`src/modules/<domain>/` 内自带 routes/services/repo/migrations/i18n。
3.  **重活一律下放 sidecar**：AI 推理、媒体转码、索引扫描、同步执行全部独立进程。

### 3.1 进程模型（v3.0 定案）

**`electron/main` 只做外壳**（窗口 / 托盘 / 单实例 / 更新器）；**内核跑在 `utilityProcess`**（Electron 官方多进程 API，Node 环境、可独立重启）。

| 进程 | 职责 | 崩溃影响 |
| --- | --- | --- |
| `main` | 外壳、托盘、更新、生命周期 | 退出应用 |
| `kernel`（`utilityProcess`） | Fastify + 内核 + 域模块 | **只影响服务，外壳可重新拉起** |
| `ai-infer` / `media` / `indexer` / `sync` | 重活 | 仅该 sidecar，任务重投 |

-   收益：API 与 UI 互不拖累；内核崩溃可独立重启；外壳先起、服务并行就绪。
-   ⚠️ **不要在 `main` 里直接 `require` 内核** —— 现状正是这样，是"单进程巨石"的根因之一。

## 4\. 技术选型

| 层 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | **TypeScript（strict）** | 主进程编译到 CJS（Electron 兼容），sidecar 用 ESM |
| HTTP | **Fastify** + `@fastify/swagger` + `@fastify/websocket` | 性能、schema 校验、原生 OpenAPI |
| 契约/校验 | **TypeBox**（与 Fastify route schema 同源） | 单一真源，一路生成 OpenAPI → Dart |
| DB | **better-sqlite3 12.11.1**（Electron 44 实测可用）+ **Kysely**；`node:sqlite` 为可选优化 | 类型安全；主库选型见 §6.1 |
| 迁移 | **Kysely migration**（版本化、可回滚） | 替代手写 `ensureColumns` |
| 向量 | **sqlite-vec**（从上游独立引入） | ANN 索引，告别全量余弦 |
| 队列 | 自建 **SQLite 持久化队列** | 优先级/限流/暂停/进度/重试/撤销；不引 Redis |
| 日志 | **pino** | Fastify 原生，结构化 |
| 实时 | Fastify WebSocket + **yjs** | 协同编辑器保留 |
| Sidecar 通信 | NDJSON over named pipe（Windows）/ unix socket | 超时、心跳、崩溃重启 |
| 客户端 | **Flutter 单栈**（`flutter_ohos` 覆盖鸿蒙） | §10/§11 |
| 客户端本地库 | **SQLite + Drift** | 类型安全 ORM + 迁移机制（§6.5） |
| 测试/质量 | **vitest** + **ESLint** + **Prettier** | §18 / §27 |
| 产物命名 | `D<NNN>`（避免 dist\_vN 序号） |  |

### 4.1 版本基线（v3.2 已核实）

> ✅ **已核实（2026-10-27 实测）**：Electron **44.9.0** / Node **24.22.0** / ABI **149**。  
> `better-sqlite3 12.11.1`、`node-pty`、`node-datachannel`、`sharp`（libvips 8.17.3）**全部实测可用**（`npm run smoke:abi` → **4/4 passed**）。  
> 旧 README 的「better-sqlite3 最高支持 Electron 37」**已过时并已修正**；Electron 版本已**精确锁定**（去掉 `^`）。

| 组件 | 基线 | 说明 |
| --- | --- | --- |
| Electron | **44.9.0**（精确锁定，不带 `^`） | 变更 = 全部原生模块重编 + 回归；升级前必须跑 `npm run smoke:abi` |
| Node | 跟随 Electron 内置 | 不单独安装 Node |
| TypeScript | 5.x 最新 stable（`strict`） |  |

| better-sqlite3 | **12.11.1**（Electron 44 实测可用，SQLite 3.53.2） | 若将来 `node:sqlite` 验证通过可移除；见 §6.1 |

| flutter\_ohos | **必须与 Flutter 3.47 配套** | 红线 6；单方面升 Flutter 会断鸿蒙 |
| HarmonyOS | modelVersion 6.0.2（现状） |  |
