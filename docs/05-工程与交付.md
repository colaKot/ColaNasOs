## 14\. 阶段任务卡（服务端 SP0–SP4 ／ 客户端 CL0–CL4）

> 每卡：**目标 → 关键任务 → 交付物 → 验收标准 → 风险**。  
> 纪律：批量改代码先备份；每阶段可独立发布/回滚；验收不过不进下一步。  
> **并行关系**：服务端 SP0–SP2 与客户端 CL0–CL1 可并行；**SP1 与 CL1 是接缝**（契约层）。

### 服务端（纯 D）

#### SP0 骨架

-   **目标**：新架构端到端跑通闭环。
-   **关键任务**：`kernel/`（ModuleRegistry/Router/Db/Migration/Queue/Contract/I18n）；**内核以 `utilityProcess` 启动、`main` 只做外壳（§3.1）**；Electron 外壳最小可运行（单实例/托盘）；**只迁 `files` 一个域模块**；`tool/gen.ts` 出 OpenAPI。
-   **交付物**：可启动服务端；`/openapi.json`；`files` 全链路通。
-   **验收**：服务能起；`files` 上传/下载/列目录通过；TS 编译 0 error；OpenAPI 路径数与模块声明一致；记录启动耗时；**`npm run smoke:abi` 4/4 通过**。
-   **风险**：Electron 外壳与内核 TS 编译目标（CJS/ESM）冲突 → 主进程先用 CJS。

#### SP1 契约链路

-   **目标**：契约驱动客户端。
-   **关键任务**：TypeBox→OpenAPI→Dart `ApiClient`；AppRegistry 生成（6 端）；i18n 键骨架生成（13 语言）。
-   **交付物**：`tool/gen.ts` + 生成物。
-   **验收**：`tool/gen.check.ts` 绿；Flutter `dart analyze` 0 error；i18n 键缺 0。
-   **风险**：Dart 生成器对 Fastify schema 特性支持不全 → 限定 schema 子集。

#### SP2 Sidecar 抽取

-   **目标**：重活下放独立进程。
-   **关键任务**：`SidecarSupervisor` + 协议；`ai-infer` / `media` / `indexer` 从现有 `workers/` 与 `utils/` 移植；TaskQueue 接管。
-   **交付物**：三 sidecar 可独立启停；任务进度可见。
-   **验收**：基准数据（缩略图 500 张耗时、AI 四模型单张耗时、主服务启动时间）**对比现状并写入文档**；sidecar 崩溃任务自动重投。
-   **风险**：ONNX 会话串行约束；`onnx_models` 路径回退。

#### SP3 域模块迁移（分批）

-   **目标**：现有 34 个 api 模块逐域并入 `src/modules/`。
-   **建议顺序**：`files` → `auth/user/security` → `photo` → `video` → `music` → `book` → `notes/editor` → `monitor/process/terminal/transmission` → `discover/transfer/encryptedSpace`。
-   **交付物**：每域一个模块目录 + migrations + i18n + routes。
-   **验收**：每域端到端回归通过；**对照附录 B 功能覆盖台账逐项打勾**；单模块故障不影响其他域。
-   **风险**：`photo`/`video` 体量最大 → 按附录 B 功能需求逐项实现，并以**黑盒对照**旧程序输出做验收。

#### SP4 更新器与发布

-   **目标**：可发布、可升级。
-   **关键任务**：版本目录式更新器（替代 asar 原地重写）；打包脚本（产物 `D<NNN>`）；安装器；**包签名与校验（sha256 + 代码签名 + 防降级：版本号必须单调递增）**；数据初始化流程。
-   **验收**：干净机器可安装运行；版本目录式升级成功、回滚可用；数据不丢。
-   **风险**：更新器与单实例锁/托盘生命周期交互。

### 客户端（K1）

#### CL0 拆包骨架

-   **目标**：monorepo 与 6 端工程就位。
-   **关键任务**：建 `packages/{nas_core,nas_ui,nas_media}` 与 `apps/{desktop,mobile,web,tv_android,tv_apple,harmony}`；独立端改为依赖细包。
-   **交付物**：可编译的 6 端骨架。
-   **验收**：6 端构建通过；`photo_client`/`music_client`/`sync_client` 改依赖后仍可编译。
-   **风险**：`flutter_ohos`/tvOS 工程初始化踩坑。

#### CL1 契约接入

-   **目标**：客户端消费生成的契约。
-   **关键任务**：接入生成的 `ApiClient`；AppRegistry 驱动 6 端入口；i18n 键接入。
-   **交付物**：`files`（及后续域）在 6 端可用。
-   **验收**：`dart analyze` 0 error；入口新增零手改；i18n 键一致。
-   **风险**：与 SP1 生成器口径对齐。

#### CL2 布局收敛

-   **目标**：消灭桌面/移动两套并列实现。
-   **关键任务**：`core/platform` 抽象 + `responsive` 布局层；统一图片/缓存管线；`Obx` 重建范围规约。
-   **验收**：试点域（`video`/`photo`）桌面+移动表现一致；交互回归通过。
-   **风险**：复杂页（地图/播放器/编辑器）保留自研组件，不强行泛化。

#### CL3 性能专项

-   **目标**：用户可感知提速。
-   **关键任务**：启动首帧优化；列表/瀑布流虚拟化；图片解码管线；本地 DB 索引优化；地图渲染（沿用"Rx 读点决定重建范围"经验）。
-   **验收**：首屏时间、列表滚动帧率、地图拖动帧率**量化前后对比**。
-   **风险**：低。

#### CL4 6 端统一

-   **目标**：web / 鸿蒙 / 电视端纳入统一栈。
-   **关键任务**：web 试 `--wasm`；鸿蒙接 `flutter_ohos`；`tv_android` D-pad 遥焦；`tv_apple` Flutter 化或保留 Swift 桥接。
-   **验收**：6 端功能冒烟通过；鸿蒙与 Flutter 主线版本对齐。
-   **风险**：`flutter_ohos` 非官方、tvOS 官方不支持（见 §15）。

## 15\. 工程红线

1.  **Electron ABI 原生模块**：`better-sqlite3` / `node-pty` / `node-datachannel` 每次 Electron 变更必须 `@electron/rebuild`，并用 `npm run smoke:abi`（即 `tool/check/abi-smoke.js`，内部以 `ELECTRON_RUN_AS_NODE=1` + `electron.exe` 验证，**不能用系统 node 跑**）确认。**已核实 44.9.0 下 4/4 通过**（SQLite 3.53.2 / libvips 8.17.3）。
2.  **ONNX 保持稳定版本**：实测 `onnxruntime-node` 1.30 在 Windows+DML 上硬回归（`webgpu` 与 `dml` 互斥致会话全废、CLIP 崩进程、DETR/SigLIP 慢 ~90%）。**继续用 1.20**；`getBestExecutionProviders()` 必须显式排除 `webgpu`。
3.  **SQLite 变量上限 999**：批量 `whereIn` 分片（400/批）。
4.  **单实例锁**：`app.setPath` 必须在取锁之前。
5.  **`onnx_models` 不进 asar**：走 `extraFiles`；保留 `resolveBundledPath` 回退。
6.  **`flutter_ohos` 版本对齐**：非官方 fork，必须与 Flutter 主线版本配套，禁止单方面升级 Flutter 而不升 fork。
7.  **`tv_apple` 官方无 Flutter 支持**：优先用社区方案验证；不通过则**保留 Swift 壳 + 桥接**，不阻塞其余 6 端。
8.  **独立端依赖重排**：`photo_client` / `music_client` / `sync_client` 从 path 依赖整份 app 改为依赖 `nas_core`/`nas_ui` 后，须跑各自自检脚本（`_check_standalone_*.py`）。
9.  **原生资源随包**：`subfont.ttf`、`onnx_models/**`、`vendor/sqlite_vec/**`、`database/geonames.sqlite` 必须随包。
10.  **批量改文件纪律**：先备份 → 脚本"读→改→校验→通过才落盘" → 精确替换配 `assert count` 双重校验；**任何 assert 失败直接抛错、绝不落盘**。
11.  **事务与事件循环**：`better-sqlite3` 是**同步 API**，会阻塞 Node 事件循环。**单事务 ≤ 50 ms**、**事务内禁止 `await` / 文件 IO / 网络**、大事务拆批（参照 §6.1 批量写），慢查询 > 100 ms 必须记日志。违反按性能缺陷处理。
12.  **代码隔离（v6.0 硬红线）**：**禁止**复制 / 移植外部源码、资源或译文；第三方库只能从**上游**引入。评审发现即阻断合并（§0.1）。
13.  **AGPL 默认禁止（v8.2 调整）**：**默认不引入**任何 AGPL-3.0 组件（含 sftpgo / openlist / AList）。确需引入时**必须同时满足五条件**：① 独立进程运行、仅经 CLI/API 调用；② **不修改**其源码；③ **不静态链接**、不并入同一二进制；④ 法务**书面确认**；⑤ SBOM 中**显式标注**。缺一即阻断。GPL 组件（FFmpeg）同样只能独立进程调用，且随包分发须提供源码（§37、§42）。
14.  **巨石模块拆分纪律**：`tool/split/split-module.js <book|video|sync|photo|music>` 只做**机械搬运**
    （`index.ts` → `util.ts` + `migrations.ts` + `helpers.ts` + `routes/*.ts`），改写前务必备份原 `index.ts`。
    拆完必须过三道校验：`tsc --noEmit` → 该模块 smoke → `npm run gen.check`（**契约 `paths` 数量与内容不得变化**，变了说明路由注册顺序或 schema 被动了）。
    已知的三个坑：`app.addSchema(...)` 必须原样留在 `register` 最前（被当路由搬走会让 `$ref` 解析失败）；`const x =` 要区分**函数**与**常量**（只工厂化函数，常量留在块内）；
    `Date.now()` 这类成员调用不能被 `now(` 的批量替换误伤（用 `(?<!\.)` 负向断言）。

## 16\. 风险登记

| # | 风险 | 影响 | 缓解 |
| --- | --- | --- | --- |
| R1 | 服务端 TS 重写工程量巨大、周期长 | 高 | 分阶段双轨；先打通 SP0 闭环再铺量 |
| R2 | `photo`/`video` 实现回归面广 | 高 | 按功能需求逐项实现；建回归清单 |

## 17\. 性能基线与目标（v3.0 新增）

> ⚠️ **没有数字就没有"更快"**。本节定义指标、测量方法与门槛；目标值在 SP2 实测现状后回填。

| 指标 | 测量方法 | 目标 |
| --- | --- | --- |
| 服务端冷启动 → `/health` 就绪 | 计时（3 次取中位） | ≤ 现状，且 ≤ **3 s** |
| API P95（列表/详情典型接口） | `autocannon` 压测，真库 | ≤ **200 ms** |
| 缩略图吞吐 | 500 张真实 JPEG，串行 + 并发 4 | ≥ 现状（基准脚本） |
| AI 单张推理 | EdgeFace / DETR / SigLIP / CLIP 分模型 | ≥ 现状（**ONNX 版本冻结**） |
| 向量检索 P99（10 万级） | `sqlite-vec` Top-20 | ≤ **50 ms** |
| 内存峰值（空载 / 索引中） | 进程 RSS | 空载 ≤ **300 MB** |
| 客户端首屏 · desktop/mobile | 冷启动到首帧 | ≤ **1.5 s** |
| 客户端首屏 · web | 冷启动到首帧 | ≤ **3.0 s**（Flutter web 现实值） |
| 客户端首屏 · TV | 冷启动到首帧 | ≤ **2.5 s** |
| 列表滚动帧率 | 瀑布流 1 万项 | ≥ **55 fps** |

**规则**：基准脚本落在 `tool/bench/`，结果 JSON 入 `docs/bench/`；**每次 SP/CL 阶段收尾必须重跑并对比**，劣化即阻断。

## 19\. 安全设计（v3.0 新增）

| 面 | 措施 |
| --- | --- |
| Electron | `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`、禁用 `remote`；`preload` 只暴露白名单 API |
| 内核 IPC | named pipe 带随机 token + 进程内校验；`utilityProcess` 不接受外部连接 |
| API | JWT + scope + 路由级权限；登录/敏感接口**速率限制** |
| Sidecar | 仅内核可连；参数校验（TypeBox）；不暴露网络端口 |
| 加密空间 | 密钥只存内存、不落日志；错误信息不回显密钥；退出时擦除 |
| 审计 | 写操作（删除/移动/权限/分享）落审计日志，含 uid/IP/时间/目标 |
| 脱敏 | 日志中文件路径与文件名**默认脱敏**，诊断包导出前二次过滤 |

## 20\. 可观测性与运维（v3.0 新增）

-   **日志**：pino 结构化、分级（error/warn/info/debug）、按模块分 child logger、**自动脱敏**。
-   **健康检查**：`GET /health`（进程存活）、`GET /ready`（DB/迁移/sidecar 就绪）。
-   **队列仪表**：`GET /api/v1/admin/queue` 返回各任务类型 pending/running/failed 与吞吐。
-   **一键诊断包**：版本、配置（脱敏）、队列快照、DB 统计、最近错误 —— NAS 产品排障必需。
-   **崩溃上报**：默认**离线关闭**；开启时只传堆栈与版本，不含路径/文件内容。

## 35. 文档体系（v5.0 新增）

| 文档 | 来源 | 维护方式 |

| ADR | `docs/adr/` | 每个架构决策一篇（§26） |

| 运维手册 | 人工 | 安装 / 升级 / 排障 / 诊断包 |
| 用户手册 | 人工 | 按端分册 |
| 升级指南 | 人工 | 版本升级的数据与配置迁移 |
| 功能覆盖台账 | 本文附录 B | 每域迁移时更新 |
| 数据表映射 | 本文附录 C | schema 变更时更新 |

## 36. 代码规范与协作（v5.0 新增）

| 项 | 规则 |
| --- | --- |
| 分支 | `main`（可发布）/ `feat/<域>-<描述>` / `fix/<描述>`；**禁止直接推 main** |
| Commit | `<type>(<scope>): <summary>`；type ∈ `feat/fix/refactor/perf/test/docs/chore` |
| Review | 每 PR 至少 1 人；**必须确认未触碰 §15 红线** |
| 命名 | 目录/文件 `kebab-case`；类型 `PascalCase`；常量 `UPPER_SNAKE`；i18n key 点分 |
| 类型 | `strict: true`；**禁止 `any`**（必要时 `unknown` + 收窄） |
| 提交前 | `pnpm check`（编译 + lint + 单测 + 契约 + i18n） |
