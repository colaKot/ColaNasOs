## 22. 数据策略（v6.0 定案：不迁移）

> **从空库开始，不导入外部数据。**

-   **不导入**：旧库（`photo_index` / `video_index` / AI 结果 / 用户表）一律不迁移。
-   **文件重新索引**：用户的媒体文件仍在其磁盘上，由新项目**重新扫描生成**（这是"重新索引"，不是"数据迁移"）。
-   **schema 自由设计**：按本项目领域模型定义（附录 C 仅作**需求参考**）。
-   **代价**：首次索引耗时 → 由 §22.1 的渐进可用 + 进度可见 + 断点续跑缓解。

### 22.1 首次索引与冷启动体验（v3.1 新增）

-   **渐进可用**：库文件就绪即可浏览目录/时间轴骨架，AI 结果（人脸/OCR/场景/活动）后台补齐，**不做"全量索引完成才开放"**。
-   **进度可见**：`/ready` 暴露索引阶段与百分比，客户端顶部展示。
-   **可暂停/限速**：首次导入期默认降低 AI 并发，优先保证前台 IO。
-   **断点续跑**：进度按 `gen_*` 标记持久化，中断后可继续。

## 26\. 决策索引（ADR 摘要，v3.1）

> 本表只是**摘要索引**。每条完整 ADR 须含 **背景 / 备选方案 / 决策 / 后果** 四要素，落在 `docs/adr/ADR-NNN-<slug>.md`；新增架构决策必须先写 ADR 再进正文。

| 编号 | 决策 | 关键理由 |
| --- | --- | --- |
| ADR-001 | 服务端走**纯 D**，不做插件框架 | 纯 D 可停靠；先 B 再 TS 化会返工 |
| ADR-002 | 主库**维持 SQLite** | 单机零运维 + 量级未触顶；换库收益低 |

| ADR-004 | 内核跑 **`utilityProcess`** | 与 UI 隔离、可独立重启 |
| ADR-005 | indexer 走**批量写协议**（500 行/批） | 主库唯一写者 + 避免 `SQLITE_BUSY` |
| ADR-006 | **AppleTV 保留 Swift 原生壳** | Flutter 无 tvOS 引擎 |
| ADR-007 | HTTP 用 **Fastify** 而非 Express 5 | schema 即契约；摆脱 `_router` 依赖 |
| ADR-008 | 部署形态**仅桌面**（不做 Docker / 无头） | 聚焦单机体验与更新链路；内核/外壳已分离，未来可补 |

## 29\. 许可与合规（v3.0 新增）

-   项目本体 **GPL-3.0**。
-   **独立性（v6.0）**：本项目为**独立实现**，界面、数据模型与译文均按本项目架构重新设计；产品化思路的参考来源见 `README` 的「致谢与参考」。
-   `onnx_models/**` 各模型许可**逐个核对并记录**（EdgeFace / PP-OCR / SigLIP / CLIP / DETR 可能不同，尤其"可商用"条款）。
-   第三方依赖做一次**许可扫描**（含原生库 `libs/*`），冲突项在发布前清理。
-   不在包内分发无再分发许可的二进制。

## 41. 新旧共存与切换（v7.0 新增）

> 用户可能在同一台机器上装着其他 NAS 软件，需明确"能否共存、怎么切、怎么退"。

| 项 | 结论 |
| --- | --- |
| 安装共存 | ✅ 可以：appId 不同（`com.colanas.os` vs 旧 appId），数据目录不同 |
| 数据目录 | `%APPDATA%\colanas_os_server`（互不影响） |
| 端口 | ⚠️ **默认端口必须错开**，冲突时自动探测并在设置页提示 |
| 开机自启 / 托盘 | ⚠️ 两者都启用会冲突 ⇒ 首次启动检测并**提示关闭另一个** |
| 媒体目录 | ⚠️ 两个服务同时扫描会重复 IO、争抢文件锁 ⇒ **建议停旧再启新** |
| 切换步骤 | 停旧 → 装新 → 配置源目录 → 等待索引（§22.1）→ 验证 → 卸载旧（可选） |
| 回退 | 卸载本项目即可；其他软件的数据**从未被修改**（§22 空库起步） |

## 45. 并发与一致性（v8.0 新增）

| 场景 | 策略 |
| --- | --- |
| 元数据并发修改 | **乐观锁**：业务表带 `version`，更新 `WHERE version=?`；不匹配返回 **409** |
| 写冲突 | 默认**检测并提示**（不静默覆盖）；可选"覆盖 / 合并 / 保留两者" |
| 协同编辑 | yjs（CRDT）自动合并；**仅限 notes / editor**，不用于文件元数据 |
| 同名文件上传 | 策略可配：覆盖 / 重命名 / 跳过 / 保留两者（默认**重命名**） |
| 重复提交 | 写接口支持 `Idempotency-Key`，同键返回首次结果 |
| 事务边界 | 单写者 + 短事务（§15 红线 11）；禁止长事务跨 await |

## 47. 运行期故障恢复（v8.0 新增）

| 故障 | 处理 |
| --- | --- |
| DB 完整性 | 启动执行 `PRAGMA quick_check`；失败 → 从最近快照恢复 |
| WAL 崩溃 | 正常由 WAL 自动恢复；异常走快照 |
| 快照 | **每日自动 + 升级前强制**；保留 N 份；位置与 DB 同盘优先 |
| 磁盘满 | 写入前检查余量；低于阈值进入**只读模式**并告警 |
| 数据损坏 | 索引类数据可重建（重置 `gen_*`）；**用户数据不可重建**，只能从备份 |
| sidecar 崩溃 | supervisor 重启 + 任务重投（§7） |
| 断电 | 任务队列持久化；重启后恢复未完成任务并标记中断项 |

> ⚠️ 原则：**能重建的（索引/AI 结果/缩略图）允许重建；不能重建的（用户文件、元数据）必须有备份**。

## 48. 缓存架构（v8.0 新增）

| 层 | 内容 | 失效 |
| --- | --- | --- |
| HTTP | `ETag` + `Cache-Control`；内容寻址资源长缓存，API 短缓存 | 内容 hash 变化 |
| 服务端 | 缩略图磁盘缓存 + 热数据内存 LRU | TTL + 显式失效 |
| 客户端 | 图片/列表 LRU + 离线快照（§11.2） | 版本号 / 时间戳 |

- 缓存键：`hash(资源 + 参数 + 版本)`，**版本变了键就变**，避免脏读。
- 击穿保护：同键请求**单飞（single-flight）**，只有一个回源。
- ⛔ **禁止**缓存跨用户的未鉴权数据。

| 用户权利 | 支持导出/删除本人数据（按地区法规） |

## 55. 部署形态（v9.0 定案：仅桌面）

> **当前只支持 Electron 桌面应用**（内置服务端），**不做 Docker / 无头服务器 / NAS 套件**。

| 项 | 决策 |
| --- | --- |
| 形态 | Electron 桌面应用（含内置服务端内核） |
| 目标平台 | **Windows x64 / macOS（x64 + arm64）/ Linux 桌面** |
| 数据目录 | `%APPDATA%\colanas_os_server`（Win）/ `~/Library/Application Support/...`（mac）/ `~/.config/...`（Linux） |
| 服务暴露 | 本机 HTTP + 局域网访问（供移动端 / TV / Web 连） |
| 更新 | 桌面版本目录式更新器（SP4） |
| 自启 | 可选（登录启动 + 托盘常驻） |

**明确不做**：Docker 镜像 / 无头 systemd 服务 / 群晖·威联通套件包 / 纯 CLI 服务器模式。

**取舍与影响（如实记录）**：

- ⚠️ **放弃 Linux 服务器与成品 NAS 用户群**——这是 NAS 产品的主力场景；无 GUI 的 NAS **装不了**（Electron 需要显示环境）。
- ✅ **扩展位已预留**：内核与外壳已分离（§3.1 `utilityProcess`），未来若做无头，只需**替换外壳 + 去掉 GUI 依赖**，**内核无需重写**。
- 缓解：带桌面的 Linux 发行版仍可运行桌面版；局域网内其他设备通过 HTTP 访问。

> **ADR-008**：部署形态仅桌面。理由：先聚焦单机桌面体验与更新链路；后果：不具备无 GUI 环境部署能力（未来可补）。

## 57. 硬件要求（v9.0 新增）

| 项 | 最低 | 推荐 |
| --- | --- | --- |
| CPU | 4 核 x64（**AVX2**） | 8 核+ |
| 内存 | 8 GB | 16 GB+ |
| 系统盘 | 20 GB 可用 | SSD |
| 存储 | HDD/SSD 均可 | SSD 系统 + HDD 数据 |
| GPU | 无（CPU 推理） | **支持 DirectML 的 GPU**（Win）/ Metal（mac） |
| 网络 | 千兆 | 2.5G+ |
| 系统 | Win 10 1809+ / macOS 12+ / Ubuntu 22.04+ 桌面 | 最新 |

- **AI 降级**：无 GPU → CPU 推理（约慢 5–10 倍），或关闭重模型（DETR / 活动）。
- **空间预估**：索引 + 向量约占原库 **5–10%**（照片库 100 GB → 约 5–10 GB）。
- 不满足最低配置时，安装器应**明确提示**而非静默降级。

## 58. 威胁模型（v9.0 新增）

| STRIDE | 场景 | 缓解 |
| --- | --- | --- |
| **S**poofing | 伪造 JWT / 配对码冒充 | 短 TTL + 刷新令牌 + 设备绑定（§19） |
| **T**ampering | 篡改上传文件 / 配置 | 校验和 + 完整性检查 |
| **R**epudiation | 否认操作 | 审计日志（§19、§54） |
| **I**nformation disclosure | 路径穿越 / 越权读 | 路径规范化 + 逐请求权限校验 |
| **D**oS | 大文件 / 海量请求 | 速率限制 + 配额 + 超时 |
| **E**levation | 子账号提权 | scope + **服务端**权限判定（不信客户端） |

**攻击面清单**：局域网 HTTP 接口、远程 P2P 通道、上传接口、模型/更新下载、第三方依赖（供应链）。

## 61. 数据生命周期（v9.0 新增）

| 层 | 介质 | 策略 |
| --- | --- | --- |
| 热 | SSD | 最近/常用数据、缩略图缓存 |
| 温 | HDD | 主存储 |
| 冷 | 归档盘 / 外部 | 长期不访问，按策略迁移 |

- **去重**：`content_md5`（§9.4），仅对静态照片/文档启用（视频不默认去重）。
- **压缩**：图片可选有损/无损；视频可转码为高效编码（§7.3）。
- **清理**：回收站 TTL、缓存 LRU、日志轮转（§48 / §54）。
- ⚠️ **归档迁移必须可逆**，且迁移前后校验 `content_md5`。

## 63. 成本模型（v9.0 新增）

| 项 | 估算方式 |
| --- | --- |
