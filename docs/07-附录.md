## 附录 E：架构演进对照（概念层）

> 记录本项目在架构上放弃了哪一类做法、换成了什么，用于解释设计取向；不指向任何既有实现的具体文件。

| 关注点 | 早期单体式做法 | 现在（ColaNasOs） |
| --- | --- | --- |
| 接口层 | 按域平铺的 controller / service | `src/modules/<domain>/`（`ServerModule` + 路由表） |
| AI 能力 | 进程内 worker | `sidecars/ai-infer`（独立进程） |
| 媒体处理 | 进程内 util | `sidecars/media`（独立进程） |
| 数据层 | 手写表 DDL + 运行时补列 | `src/modules/*/migrations/` + Kysely |
| 路由注册 | 应用入口集中注册 | 内核 Router + 模块 `register` |
| 客户端 API | 手写 `*_api_service.dart` | 生成的 `ApiClient`（`packages/nas_core`） |
| App 入口 | 每端各写一份 | `AppRegistry`（6 端共用） |
| 多语言 | 手工维护语言键 | `i18nRegistry` 生成键骨架 |
| UI 复用 | 各端各自实现 | `packages/nas_ui` + `apps/*` |
| `photo_client`/`music_client`/`sync_client`(path 依赖整 app) | 依赖 `packages/nas_core`/`nas_ui` |
