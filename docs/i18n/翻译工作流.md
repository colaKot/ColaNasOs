# 翻译工作流与术语表

> 对应任务：X-05。所有语言的键骨架由 `contracts/i18n.json` 生成，**译文与骨架分离**。

## 1. 唯一事实来源

| 文件 | 作用 | 谁改 |
| --- | --- | --- |
| `contracts/i18n.json` | 键清单 + 占位符声明（`{"done":"int"}` 表示 `{done}`） | 开发者 |
| `contracts/glossary.json` | 术语基线 + 禁用译法 | 产品 / 本地化负责人 |
| `packages/nas_core/lib/l10n/<locale>.json` | 各语言译文 | 译者（只填 `messages` 的值） |
| `packages/nas_core/lib/l10n/keys.dart` | 生成的常量，禁止手改 | `npm run gen:i18n` |

## 2. 流程

1. **加键**：只改 `contracts/i18n.json` → `npm run gen:i18n` → 13 个 locale 骨架自动补空值。
2. **翻译**：译者只填 `messages` 的值，键名与占位符**原样保留**。
3. **校验**：`npm run i18n.glossary`
   - 键集合必须与契约完全一致（缺键 / 多余键都报错）
   - 每个声明过的占位符必须原样出现在译文里，且不得出现未声明的占位符
   - 译文不得命中 `glossary.json` 的 `forbidden` 写法
   - 非 CJK 语言出现中文 → 记为「疑似未翻译」（提示，不阻断）
4. **发布前**：`node tool/i18n-glossary.js --strict`，此时空译文也会失败。

## 3. 占位符规则

- 契约里 `"files.upload.progress": { "done": "int", "total": "int" }` 表示译文必须同时含 `{done}` 与 `{total}`，顺序可变。
- 占位符大小写敏感，禁止翻译、禁止加空格。
- 复数/量词差异交给各语言的完整句子处理，不做拼接。

## 4. 术语约定

- 产品名与缩写（NAS）不翻译。
- 「断点续传 / 幂等 / 执行提供者 / 加密空间」等按术语表统一译法，避免同义词混用。
- 禁用译法用于拦截机翻直译（例如 `Breakpoint resume`、`网络附加存储`）。
- 新增语言时先在 `glossary.json` 补该语言的推荐译法，再开始翻译。

## 5. 与门禁的关系

`npm run verify` 已包含 `i18n.glossary`，键/占位符/术语不一致会直接让 CI 失败；
译文质量（是否通顺）仍由人工评审，脚本只保证「结构与术语」不错。
